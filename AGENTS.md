# Работа над сервисом банвордов

- Писать сервис на Go; новых runtime-зависимостей Node.js не добавлять.
- Отвечать по-русски. Сервис самостоятельный; git init, commit, push и deploy — только по явному разрешению.
- Любое изменение хендлеров, маршрутов, схем или HTTP-статусов сопровождается обновлением `openapi.json` в той же задаче. Перед передачей запускать `make test` (Go race detector и 100% statement coverage), `make check` (go vet и gofmt) и сборку.
- Покрывать исполняемую логику тестами: контракт, канонизация sp/1, коллизии, валидация JWT, JWKS, ограничения и ошибки. В тестах подменять auth/JWKS; не обращаться к настоящему Twitch или production API.
- Публикация словарей — только файлами при деплое. Опубликованные `data/versions/*.json` неизменяемы: добавлять новую версию, сохранять старую в manifest. Не добавлять runtime API записи без запроса.
- Короткий hash1 не уникален. Lookup возвращает все совпадения; не выбирать произвольный словарь при коллизии.
- JWT приходит только от Caddy в `X-Auth-Token`. Не принимать пользовательские service-токены напрямую и не логировать заголовки, слова или секреты.
